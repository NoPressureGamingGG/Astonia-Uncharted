# Project Doctrine

## Mission

Create a bold, maintainable Astonia reimagination on Server 3: experiment,
try new ideas, and push the existing systems to creative limits—but always with
a clear reason. The work should be fun, improve the project owner’s coding
skills, and remain understandable enough to evolve or port later.

## Principles

1. **Creative purpose.** New mechanics begin with player value and a design why.
2. **Learn the system.** Map existing interactions before changing them.
3. **Human gameplay expertise.** When code behavior and lived game experience
   disagree or are unclear, ask the project owner.
4. **Traceability.** Every meaningful change has a focused commit and changelog.
5. **Reversible experiments.** Scope new mechanics and document rollback.
6. **Upstream respect.** Preserve attribution and import upstream changes
   deliberately, never as accidental bulk copies.

## Boundaries

- Server 35 is a later evaluation target, not a dependency of this codebase.
- PathOfAstonia is historical reference only.
- Player data, credentials, and machine-specific settings remain outside Git.
